现有视频250ms源帧/解码新鲜度门限只决定旧图是否继续显示；服务侧姿态250ms门限

## 测量方法与证据

### 视频曝光到显示

1. 固定并记录相机、同步/校正方式、实际每眼输入尺寸/FPS、预处理、codec/码率、
   头显/浏览器版本、投影参数、网络条件和测试持续时间。冻结配置和完整720p60分别记录。
2. 使用可识别的帧号/亮暗变化目标；以该帧指定ROI的**曝光中点**为t0，
   以头显相应像素第一次显示同一帧变化的出光时刻为t1，计算 `t1 - t0`。
   优先使用相机曝光有效信号及头显镜片后的光电传感器，在同一个采样时基记录；
   滚动快门须明确ROI位置、曝光时间和行时序。触发时间若不等于曝光中点，须实测校准。
3. 若只有高速外部摄像机同时拍摄目标LED和头显镜片中的画面，报告**光到光**延迟，
   并记录采样帧率/误差。该测量包含目标变化等待相机曝光的时间，不能直接改名为曝光延迟，
   也不能按标称相机FPS随意减去半帧；曝光口径未取得时本项仍标**未验收**。
4. 每个配置/网络场景采集至少2000个可匹配显示样本，保留序列与测量误差，报告P50/P95/P99/max。
   双目分别观察，按较差眼结果检查暂行门槛；检查两眼帧号配对。
   未显示帧、停帧和恢复窗口单独记录数量/持续时间，不能删除异常片段后只报流畅区间。
   测量误差跨越门槛时不判通过。

`frame_age_ms`、requestVideoFrameCallback新鲜度、接收FPS、解码完成时间和主观流畅度，
均不能替代上述曝光到最终出光测量。相机时间戳、PC时间戳和Quest时间戳若未校准时基，
不能直接相减作为绝对延迟。

### 姿态、告警与恢复

- 在消费端独立控制循环记录最后有效新帧的本地单调收包时间、50ms告警/降速事件、
  100ms保持事件、故障解除和用户确认事件；同步记录seq、session、每手tracked与外部来源事件。
  记录控制循环周期/最大调度迟延和实际控制命令变化。测试中正常收包不能自动消除故障锁定。
- 用共同外部时基或可匹配事件记录故障注入、HUD第一次可见、旧画面隐藏和控制动作。
  HUD可见时间须从镜片或头显可见录制取得，不能仅检查普通网页文字。
- 网络可达口径为断网后PC入口第一次成功响应未缓存的 `GET /api/video/config`（TLS/API可达）。
  当前页面按1秒周期探测，应记录探测带来的时间不确定性；这不保证媒体UDP路径已经恢复。
  从该成功响应开始，分别计时到第一帧新的有效姿态及第一帧新解码视频；目标≤5秒。
  至10秒仍失败时对应XR HUD必须可见失败提示。另记录实际网络恢复时刻到探测成功的间隔。
- 无PC收包ACK的头显只能判断姿态连接与本地发送堵塞，不能判断PC实际新鲜度。
  头显解码故障也不经 `/ws` 回传；视觉依赖的机器人闭环必须接入接收端故障监督。
  没有这项上层反馈与动作证据，就不能把“HUD提示可见”判成“机器人已降速/保持”。
